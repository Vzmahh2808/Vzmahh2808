# Контракт турнира арены (Solana, Anchor 1.2)

Программа `dungeon-arena` хранит в блокчейне всё, что нужно для честного турнира агентов:
- деньги: взносы и спонсорский призовой фонд;
- способ получить seed подземелья, который заранее не знает никто;
- таблицу лидеров;
- выплаты призов.

## Как проходит турнир

1. **`create_tournament`.** Организатор публикует:
   - хеш своего секрета, sha256 от 32 байт;
   - номер будущего слота Solana;
   - время окончания и крайний срок раскрытия секрета;
   - взнос и число попыток на взнос;
   - долю организатора (до 20%) и доли призов (до 5 мест, в сумме 100%).

   Деньги лежат в сейфе (токен-счёте), которым распоряжается только адрес турнира (PDA).
2. **`fund`.** Кто угодно добавляет деньги в призовой фонд.
3. **`record_slot_hash`.** Когда нужный слот прошёл, кто угодно вызывает эту инструкцию. Контракт сам читает хеш первого блока в этом слоте или после него из системных данных `SlotHashes`, так что организатор не может его подменить. Там хранятся последние 512 слотов, поэтому вызвать инструкцию нужно в течение нескольких минут после слота.
4. **`enter`.** Игрок платит взнос. Сам организатор участвовать не может.
5. **`submit_result`.** Сервер арены отправляет проверенный счёт и sha256 записи партии. Контракт считает попытки и ведёт таблицу топ-5: лучший результат игрока, при равенстве выше тот, кто раньше.
6. **`reveal`.** После окончания и 15 минут на досчёт партий организатор раскрывает секрет, а контракт сверяет его с хешем. С этого момента seed знают все:

   ```
   seed = первые 4 байта sha256("dungeon-heart:v2:<адрес турнира>:<хеш слота hex>:<секрет hex>")
   ```

   Любой может переиграть опубликованные записи и сверить их хеши с блокчейном (`src/chain/tournament.ts`).
7. **`finalize`.** Кто угодно может вызвать после раскрытия. Доля организатора переводится ему, остаток становится призовым фондом.
8. **`claim`.** Победители сами забирают призы. Если игроков меньше, чем мест, доли пустых мест делятся между занятыми пропорционально.

**Если что-то пошло не так.** Организатор может отменить турнир (`cancel`), пока он открыт. Если секрет не раскрыт к крайнему сроку, отменить может кто угодно. После отмены игроки возвращают взносы (`refund`), а организатор забирает остальное, то есть спонсорские деньги (`withdraw`).

## Модель доверия

**Что гарантирует контракт:**
- организатор не выбирает хеш слота;
- организатор не может поменять секрет после объявления;
- взносы нельзя увести в обход правил выплат;
- если организатор пропал и не раскрыл секрет, игроки получают взносы обратно.

**Что держится на доверии к организатору:**
- **Честность при игре.** Организатор знает секрет, а значит и seed, поэтому через другой кошелёк может сыграть с перебором ходов. Улучшение на будущее: секрет из нескольких независимых частей или VRF.
- **Отправка результатов.** Счёт отправляет сервер организатора. Подделку или пропущенный результат видно после раскрытия, потому что записи можно перепроверить, но контракт это не наказывает. Для турниров с серьёзными деньгами нужны окно для споров перед выплатами и несколько независимых проверяющих.

## Сборка и тесты

- **Юнит-тесты логики** проверяют таблицу лидеров, деление призов и разбор `SlotHashes`. Запускаются на обычном компьютере:

  ```bash
  cargo test -p dungeon-arena
  ```

- **Интеграционные тесты** (`integration/tests/tournament.rs`) запускают собранную программу в LiteSVM вместе с настоящей программой SPL Token и проверяют:
  - полный турнир с выплатами;
  - отмену с возвратом взносов;
  - неверные параметры;
  - устаревший слот.

  ```bash
  cargo build-sbf --manifest-path programs/dungeon-arena/Cargo.toml
  cargo test -p dungeon-arena-integration
  ```

- **CI** (`.github/workflows/program.yml`) ставит инструменты Solana, собирает программу, прогоняет оба набора тестов и выкладывает `dungeon_arena.so`.

## Деплой в devnet

Адрес в `declare_id!` — заготовка. Для своего деплоя:

```bash
solana-keygen new -o target/deploy/dungeon_arena-keypair.json
solana address -k target/deploy/dungeon_arena-keypair.json   # вписать в declare_id! в programs/dungeon-arena/src/lib.rs
cargo build-sbf --manifest-path programs/dungeon-arena/Cargo.toml
solana program deploy --url devnet target/deploy/dungeon_arena.so --program-id target/deploy/dungeon_arena-keypair.json
```

# Hiddify на ПК: подключение новых прокси (подробная инструкция)

Актуально для **Hiddify App v4.1.1** (Windows / macOS / Linux). Приложение построено
на ядре sing-box и поддерживает VLESS (в т.ч. Reality), VMess, Trojan, Shadowsocks,
Hysteria2, TUIC, WireGuard.

> Названия пунктов меню ниже даны как **Русский (English)** — в приложении можно
> переключить язык в `Settings → Language`. В разных сборках формулировки могут
> немного отличаться, но расположение то же.

---

## 0. Что сначала выяснить про «новые прокси»

От формата зависит способ импорта. У тебя на руках должно быть что-то одно из:

| Что получил | Как выглядит | Способ импорта |
|---|---|---|
| Ссылка на подписку | `https://…/sub/xxxx` или `…?token=…` | Раздел 3, способ **А** (рекомендуется) |
| Ссылка на один сервер | `vless://…`, `vmess://…`, `trojan://…`, `ss://…`, `hy2://…` | Раздел 3, способ **Б** |
| QR-код | картинка | Раздел 3, способ **В** |
| Файл конфига | `.json`, `.txt`, `.yaml` | Раздел 3, способ **Г** |

Если формат неизвестен — открой ссылку в блокноте: подписка обычно отдаёт список
строк `vless://…`, закодированный в base64.

## 1. Установка или обновление приложения

**Это шаг №1, а не опциональный.** Самая частая причина «новые прокси не работают,
а старые работали» — старое ядро не умеет новый протокол (Reality, Hysteria2, TUIC,
новые варианты uTLS-отпечатков). Обновление часто решает проблему само по себе.

Скачивать только с официального GitHub:
**https://github.com/hiddify/hiddify-app/releases/latest**

### Windows
1. Скачай `Hiddify-Windows-Setup-x64.exe` (или `Hiddify-Windows-Portable-x64.zip`,
   если не хочешь ставить в систему).
2. Если стоит старая версия — сначала **полностью закрой** её из трея
   (правый клик по иконке → `Выход/Quit`), иначе установщик не перезапишет файлы.
3. Запусти установщик. SmartScreen может ругаться — `Подробнее → Выполнить в любом случае`.
4. После установки запусти **от имени администратора** (правый клик по ярлыку →
   `Запуск от имени администратора`). Без этого не включится режим TUN/VPN.

### macOS
1. Скачай `Hiddify-MacOS.dmg` (или `.pkg`). Требуется macOS 10.15+.
2. Перетащи в `Программы`. При первом запуске: `Системные настройки →
   Конфиденциальность и безопасность → Всё равно открыть`.
3. Приложение попросит пароль администратора для установки сетевого расширения —
   это нормально, без него не будет VPN-режима.

### Linux
```bash
# Debian/Ubuntu
sudo dpkg -i Hiddify-Debian-x64.deb || sudo apt -f install

# Fedora/RHEL
sudo rpm -i Hiddify-rpm-x64.rpm

# Универсально
chmod +x Hiddify-Linux-x64.AppImage && ./Hiddify-Linux-x64.AppImage
```
Для TUN-режима нужны права: запусти из терминала через `sudo`, либо разреши
capability бинарнику (`sudo setcap cap_net_admin+ep <путь_к_бинарю>`).

## 2. Чистка старых прокси (не пропускай)

Старые профили конфликтуют с новыми: приложение может молча продолжать использовать
прежний сервер или прежнюю подписку.

1. На главном экране нажми на название профиля вверху → откроется список
   **Профили (Profiles)**.
2. Удали **все** старые профили: свайп влево / правый клик → `Удалить (Delete)`.
3. `Настройки → Конфигурация (Settings → Config Options)` → внизу
   **`Сбросить настройки (Reset settings)`** — это вернёт порты, DNS и режим к
   значениям по умолчанию. Если кто-то раньше правил DNS или роутинг «под старые
   прокси», это как раз то, что ломает новые.
4. Полностью выйди из приложения (из трея) и запусти заново от администратора.

**Радикальный вариант, если ничего не помогает** — снести конфиг целиком:
- Windows: удалить `%APPDATA%\hiddify` и `%LOCALAPPDATA%\hiddify` (приложение закрыто!)
- macOS: `~/Library/Application Support/app.hiddify.com`
- Linux: `~/.local/share/app.hiddify.com` и `~/.config/hiddify`

## 3. Добавление новых прокси

### Способ А — ссылка на подписку (лучший вариант)
1. Скопируй ссылку подписки в буфер обмена.
2. В приложении: `+` (внизу справа) → **`Добавить из буфера обмена
   (Add from clipboard)`**. Если кнопки нет — `+` → `Новый профиль (New profile)` →
   вставь ссылку в поле и нажми `Добавить (Add)`.
3. Дождись `Профиль обновлён / Profile updated`. В списке появятся серверы.
4. Открой профиль → включи **`Автообновление (Auto update)`** и поставь интервал
   60 минут — тогда при смене серверов на стороне провайдера всё подтянется само.

> Если подписка не скачивается — это отдельная проблема, см. раздел 6, пункт **6.1**.

### Способ Б — одиночная ссылка `vless://` / `vmess://` / `trojan://`
Точно так же: скопировать → `+` → `Добавить из буфера обмена`. Можно вставить
**сразу несколько ссылок**, каждую с новой строки — импортируются все.

### Способ В — QR-код
`+` → `Сканировать QR (Scan QR code)`. На десктопе есть вариант
**`QR из файла / из экрана`** — выбери картинку с кодом.

### Способ Г — файл конфига
`+` → `Добавить из файла (Add from file)` → укажи `.json` / `.txt`.
Для `sing-box`-конфига нужен именно формат sing-box; конфиг от v2rayN или Clash
напрямую не подойдёт — попроси у провайдера ссылку-подписку.

## 4. Настройки, которые нужно проверить сразу после импорта

`Настройки → Конфигурация (Settings → Config Options)`:

| Параметр | Что поставить | Зачем |
|---|---|---|
| **Режим службы (Service Mode)** | `VPN (TUN)` — весь трафик системы. Если не запускается — `Системный прокси (System Proxy)` | TUN гонит через прокси игры, Telegram, CLI. System Proxy — только то, что уважает системные настройки |
| **Регион (Region)** | `Другое (Other)` | Регионы `Russia/Iran/China` включают правила, часть которых пускает трафик напрямую — именно из-за этого «прокси включён, а сайт не открывается» |
| **Удалённый DNS (Remote DNS)** | `https://1.1.1.1/dns-query` или `tls://8.8.8.8` | DNS должен резолвиться через туннель, иначе утечка и блокировки |
| **Прямой DNS (Direct DNS)** | `system` или `8.8.8.8` | |
| **Режим IPv6 (IPv6 Mode)** | `Отключено (Disable)` | Частая причина обрывов, если у провайдера кривой IPv6 |
| **Смешанный порт (Mixed Port)** | по умолчанию (обычно `12334`) | Меняй, только если порт занят другим клиентом |
| **Реализация TUN (TUN implementation)** | `mixed` | При проблемах со стабильностью попробуй `gvisor` |
| **Обход локальной сети (Bypass LAN)** | Включено | Чтобы принтеры/NAS/локалка работали напрямую |
| **URL проверки соединения (Connection test URL)** | `https://cp.cloudflare.com/generate_204` | Стандартный `gstatic.com` бывает недоступен и даёт ложное «нет связи» |

Если серверов в профиле много — на главном экране выбери группу и нажми
**`Проверить задержку / Auto select (URL test)`**, приложение само выберет самый
быстрый живой сервер.

## 5. Первое подключение и проверка

1. Нажми большую кнопку подключения на главном экране.
2. Windows при первом включении TUN попросит подтвердить установку сетевого
   драйвера (wintun) — согласись.
3. Дождись статуса **`Подключено (Connected)`** и ненулевой задержки (ms) у сервера.
4. Проверь по-настоящему:
   - открой https://ifconfig.me — должен показать IP сервера, а не твой;
   - открой https://browserleaks.com/dns — DNS-серверы не должны быть твоего
     домашнего провайдера;
   - в терминале: `curl https://ifconfig.me` (в TUN-режиме тоже должен показать IP прокси —
     если показывает твой, значит TUN не поднялся и работает только системный прокси).

## 6. Если не работает — по симптомам

### 6.1. Подписка не обновляется / «Failed to fetch subscription»
Классическая проблема курицы и яйца: домен подписки сам заблокирован.
- Подключись к любому **старому рабочему** серверу и обнови подписку уже через него.
- Или открой ссылку подписки в браузере с включённым VPN, скопируй содержимое и
  импортируй как файл/текст (способ Б или Г).
- Проверь, что ссылка не истекла и не имеет лимита по устройствам/трафику —
  спроси у того, кто выдал прокси.
- Убедись, что в ссылке нет лишних пробелов/переносов (частая беда при копировании
  из мессенджера).

### 6.2. Статус «Подключено», но интернета нет
- **Регион** стоит `Russia` вместо `Other` → раздел 4.
- **Remote DNS** не резолвится: поставь `https://1.1.1.1/dns-query`.
- Другой VPN/прокси-клиент запущен параллельно (Nekoray, v2rayN, Clash, WARP,
  корпоративный VPN) → закрой их полностью.
- Системный прокси «залип» с прошлого раза → Windows: `Параметры → Сеть и Интернет →
  Прокси` → выключи всё вручную. macOS: `Системные настройки → Сеть → Детали → Прокси`.

### 6.3. Не включается TUN / VPN-режим, ошибка прав
- Windows: только `Запуск от имени администратора`. Альтернатива — включить
  **`Режим службы (Service mode)`** в настройках: приложение поставит системную
  службу, и админ-права больше не понадобятся при каждом запуске.
- Антивирус/Defender может блокировать установку wintun-драйвера — временно
  отключи защиту на время установки или добавь папку Hiddify в исключения.
- macOS: разреши сетевое расширение в `Конфиденциальность и безопасность`.
- Как временное решение — переключись на `System Proxy`, он прав не требует.

### 6.4. Сервер подключается и тут же отваливается / «handshake failed» / «timeout»
- **Проверь системное время.** VMess и TLS-рукопожатия ломаются при расхождении
  больше ~2 минут. Windows: `Параметры → Время и язык → Синхронизировать сейчас`.
  Linux: `sudo timedatectl set-ntp true`.
- Протокол требует более свежего ядра → обнови приложение (раздел 1).
- UDP-протоколы (Hysteria2, TUIC, WireGuard) у многих провайдеров режутся —
  попробуй TCP-сервер (VLESS+Reality / Trojan) из той же подписки.
- Против DPI: `Настройки → Конфигурация` → включи **TLS-трюки / фрагментацию
  (TLS Tricks → Enable fragment)`**, и отдельно попробуй выключить **Mux**.
  Помогает не всегда и по-разному на разных сетях — тестируй по одному параметру.

### 6.5. Приложение не стартует / порт занят
```powershell
# Windows: посмотреть, кто держит порт (подставь свой Mixed Port)
netstat -ano | findstr :12334
tasklist | findstr <PID>
```
```bash
# macOS / Linux
sudo lsof -i :12334
```
Либо закрой конфликтующую программу, либо поменяй `Mixed Port` в настройках.

### 6.6. Работает в браузере, но не в играх/Telegram/терминале
Это признак того, что включён `System Proxy`, а не `TUN`. Переключи
`Режим службы → VPN (TUN)` (нужны права администратора, см. 6.3).

## 7. Как собрать логи для диагностики

Если ничего не помогло — логи покажут точную причину:
1. `Настройки → Журналы (Logs)` → включи уровень **`debug`**.
2. Воспроизведи проблему (нажми подключение, дождись ошибки).
3. `Поделиться / Экспорт (Share/Export)` — получишь файл.

Файлы логов лежат здесь:
- Windows: `%APPDATA%\hiddify\logs`
- macOS: `~/Library/Application Support/app.hiddify.com/logs`
- Linux: `~/.local/share/app.hiddify.com/logs`

**Перед отправкой кому-либо удали из лога адреса серверов, UUID, пароли и
ссылку подписки.**

  скриншотах и **не коммить в git-репозиторий** — этот репозиторий публичный.

- Скачивай приложение только с https://github.com/hiddify/hiddify-app/releases —
  в сторах и на сайтах-зеркалах попадаются сборки с бэкдорами.

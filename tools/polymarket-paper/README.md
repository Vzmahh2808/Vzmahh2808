# Бумажная торговля на 5-минутных рынках Polymarket

Программа подключается к рынкам **«Bitcoin Up or Down — 5 minutes»** и торгует
**на бумаге**. Настоящих ордеров нет, кошелёк, ключи и деньги не нужны: читаются
только публичные данные Polymarket. Задача одна: честно проверить, есть ли у
простых стратегий преимущество **после комиссий и задержек**, прежде чем
рисковать деньгами.

Одновременно работают три бумажных счёта на одних и тех же данных:

| Стратегия | Что делает |
|---|---|
| `taker` | Покупает по рынку Up или Down, когда аск дешевле «честной» цены минимум на 3¢ **после** комиссии тейкера |
| `maker` | Ставит лимитные заявки на обе стороны на 3¢ ниже честной цены («complete sets», как в ролике). Если купились обе стороны дешевле $1 в сумме, прибыль есть при любом исходе. Считает заявку исполненной, только если сделка прошла по цене **хуже** нашей. Это пессимистичная оценка |
| `maker_touch` | То же самое, но заявка исполняется, если сделка прошла **по нашей цене**. Это оптимистичная оценка |

Реальный результат мейкера где-то между `maker` и `maker_touch`. В бумажной
торговле не видно своего места в очереди заявок, поэтому точнее не сказать.

«Честная» цена — это вероятность того, что BTC закончит окно не ниже цены
открытия. Она считается по цене Chainlink (по ней рынок и закрывается), по
времени до конца окна и по текущей волатильности.

## Запуск на Windows

1. Установите **Python 3.10 или новее** с https://www.python.org/downloads/.
   В установщике поставьте галочку **«Add python.exe to PATH»**.
2. Скачайте эту папку. На странице репозитория на GitHub: **Code → Download ZIP**,
   распакуйте и откройте `tools\polymarket-paper`.
3. Дважды щёлкните **`run-paper.cmd`**. Первый запуск около минуты ставит
   зависимости в папку `.venv`.
4. Оставьте программу работать. Для первых выводов нужно **30–50 окон**, это
   2,5–4 часа. Лучше сутки, чтобы захватить и спокойные, и бурные часы.
5. **Ctrl+C** — остановить и получить итог. На вопрос «Завершить выполнение
   пакетного файла?» ответьте **N**, иначе окно закроется. Итог в любом случае
   сохраняется в `results\`.

Первое окно, на котором программа запустилась посреди окна, обычно
пропускается: для него неизвестна цена открытия.

### macOS / Linux

```bash
cd tools/polymarket-paper
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m paper live
```

## Что на экране

Через ~5 секунд после конца каждого окна выводится строка:

```
12:05 BTC → UP   | taker: +1.23$ (3 сд.) | maker: -0.40$ (8 сд.) | maker_touch: +0.60$ (9 сд.)   Σ taker +5.10$, ...
```

Здесь исход окна, результат каждой стратегии за окно и накопленный итог.
Раз в 30 секунд печатается статус: подключения, цена, честная вероятность Up
и лучшие аски в текущем окне.

После остановки выводится таблица:

| Колонка | Смысл |
|---|---|
| окон | в скольких окнах стратегия совершала сделки |
| объём $ / комисс $ | сколько потрачено на покупки и сколько из этого ушло на комиссию тейкера |
| P&L $ | итоговая прибыль или убыток |
| $/окно | средний результат за окно |
| % выигр | доля прибыльных окон |
| просадка | максимальное падение накопленного P&L от пика |
| пары | доля акций, собранных в пары Up+Down; остальное — ставка на направление |

Под таблицей для каждой стратегии написан вывод: «похоже на преимущество»,
«неотличимо от нуля», «стабильно теряет» или «мало данных». Вывод учитывает
разброс результатов (±2 стандартные ошибки), а не только знак суммы.

В `results\live-…\` лежат `summary.txt`, `windows.csv` (по окнам) и
`fills.csv` (каждая бумажная сделка). CSV открываются в Excel.

## Запись и повтор

Всё, что приходит с рынка, пишется в `data\rec-ДАТА-ВРЕМЯ.jsonl.gz`. Эту запись
можно прогнать заново с другими параметрами, не дожидаясь новых данных:

```
run-paper.cmd replay data\rec-20260923-120000.jsonl.gz --latency 500
run-paper.cmd replay data\rec-*.jsonl.gz --params my-params.json
```

Параметры задаются JSON-файлом. Возьмите за основу `params.example.json`,
удалите лишнее и поменяйте нужное. Основные параметры:

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `latency_ms` | 250 | через сколько мс ордер доходит до биржи, отмена тоже |
| `fee_rate` | из рынка (0.07) | ставка комиссии тейкера: `акций × ставка × p × (1 − p)` |
| `taker_min_edge` | 0.03 | минимальный запас taker после комиссии, $ на акцию |
| `maker_half_spread` | 0.03 | насколько ниже честной цены ставятся заявки maker |
| `maker_max_imbalance` | 20 | перекос Up/Down в акциях, после которого перевешивающую сторону больше не покупаем |
| `taker_size`, `maker_size` | 10 | акций в одной заявке (минимум на Polymarket — 5) |
| `taker_max_shares`, `maker_max_shares` | 100 | максимум акций одной стороны за окно |
| `stop_before_end_s` | 15 | не торговать в последние N секунд окна |
| `strategies` | все три | какие стратегии запускать |

Другие команды:

```
run-paper.cmd live --assets btc,eth        BTC и ETH одновременно
run-paper.cmd live --window 15             15-минутные рынки
run-paper.cmd live --minutes 240           остановиться через 4 часа
run-paper.cmd live --price-source binance  цена Binance вместо Chainlink (если Chainlink не приходит)
run-paper.cmd demo                         проверка без интернета на выдуманных данных
```

**`demo` ничего не говорит о реальном рынке.** В нём «чужие» участники нарочно
торгуют по устаревшим ценам, чтобы у стратегий были сделки. Он нужен только
чтобы убедиться, что программа запускается.

## Честно об ограничениях

Бумажный результат почти всегда **лучше** реального. Причины:

- **Наши заявки не влияют на рынок.** Настоящая заявка сдвигала бы стакан,
  и на неё реагировали бы другие участники.
- **Нет очереди.** Отсюда разница между `maker` и `maker_touch`. Когда
  участников много, реальность ближе к пессимистичному `maker`.
- **Задержка 250 мс — это мало для домашнего интернета и много против
  профи**, у которых единицы миллисекунд. Прогоните запись с `--latency 500` и
  `--latency 1000`. Если преимущество исчезает, в реальности его не будет.
- **Модель простая** (случайное блуждание цены). У серьёзных игроков есть
  стаканы бирж, фьючерсы и потоки ликвидаций.
- Ребейты мейкерам, газ и ввод-вывод денег не учтены.
- Итог окна сначала считается по Chainlink, потом сверяется с официальным
  итогом Polymarket. Число исправлений показано в итоге и обычно равно нулю.

**Как понимать результат.** Если через сутки и больше консервативный `maker`
или `taker` стабильно в плюсе, в том числе с `--latency 500`, есть смысл копать
дальше. Но это ещё не повод вкладывать деньги. Если всё около нуля или в
минусе, ответ на вопрос «работает ли» получен бесплатно.

Реальная торговля на Polymarket запрещена правилами площадки в ряде стран,
в том числе в России, Великобритании, Франции и Германии.

## Если не подключается

Программе нужен доступ к `gamma-api.polymarket.com`,
`ws-subscriptions-clob.polymarket.com` и `ws-live-data.polymarket.com`.

- «Нет ответа от gamma-api…» — эти адреса не открываются из вашей сети.
- «Цены так и не пришли» — попробуйте `--price-source binance`.
- «Часы компьютера спешат/отстают» — синхронизируйте время: Параметры →
  Время и язык → Синхронизировать. Окна рынков считаются по точному времени.

Для разработчиков: тесты запускаются командой
`python -m unittest discover -s tests -t .` (нужен `aiohttp`).
